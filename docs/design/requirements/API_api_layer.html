NUMIC requirements / API

API layer

The API layer is the single entry point to NUMIC's logic and data. It authenticates requests, checks permissions and unit scope, validates input, calls the core components and returns consistent JSON. It stays thin: scoring, rule management and data rules live in their own components.

Code APILayer API Partly exists FastAPI app in src/numic/main.py with /api/v1 scoring and measurement routes, a demo route and OpenAPI at /docs. No auth, persistence routes or admin routes yet. 12 functional · 4 non-functional · 12 must

Scope

In scope

  • Routing and request validation
  • Authentication and authorisation checks
  • Error format
  • Pagination, request IDs and API versioning
  • OpenAPI documentation

Out of scope

  • Scoring rules (SCR)
  • Rule-set storage (RUL)
  • Database schema (DAT)
  • Public demo, which scores in the browser (DEMO)

Users, data and interfaces

Users and callers

  • NUMIC front ends (CLN, DSH, ADM)
  • Integration services (EXT)
  • Developers using the OpenAPI documentation

Data it owns

  • None. Request IDs are passed to LOG.

Interfaces

  • GET /health (exists)
  • GET /api/v1/me
  • /api/v1/units, /api/v1/patients
  • /api/v1/patients/{id}/scans and measurements (manual, spreadsheet, overlay)
  • POST /api/v1/assessments (store and score)
  • POST /api/v1/score/numic-flow (stateless, no storage)
  • GET /api/v1/rule-sets, /api/v1/admin/rule-sets
  • /api/v1/assessments/{id}/decision, /api/v1/patients/{id}/outcomes
  • /api/v1/analytics/*, /api/v1/audit, /api/v1/reports/*

Functional requirements

Must needed for a first clinical pilot Should expected soon after Could useful if time allows Later future phase
IDPriorityRequirementAcceptance criterion
API-F01MustExpose a versioned JSON API under /api/v1 with OpenAPI documentation./docs lists every route with request and response schemas.
API-F02MustRequire authentication on every route except /health.An unauthenticated call to /api/v1/patients returns 401.
API-F03MustEnforce role and unit scope on every route that reads or writes patient data.A clinician scoped to Unit A requesting a Unit B patient gets 403.
API-F04MustProvide endpoint groups for me, units, patients, scans and measurements, assessments, rule sets, admin rule sets, decisions, outcomes, analytics, audit and reports.Each group appears as a tag in OpenAPI.
API-F05MustStore and score in one call for clinical use, and keep a stateless scoring endpoint that stores nothing.POST /api/v1/assessments creates a stored result; POST /api/v1/score/numic-flow returns a result and writes nothing to the database.
API-F06MustInclude the rule-set revision ID and the full explanation in every response that contains a score.Every scored response has score_version (e.g. numic_flow_levene@1) and per-layer and per-metric details.
API-F07MustReturn consistent errors: 401, 403, 404, 409 for attempts to change a published revision, and 422 naming the invalid field.Requesting a retired rule ID returns 422 whose message lists the valid IDs; editing a published revision returns 409.
API-F08MustAccept or create a request ID for every call and return it in a response header.Every response carries X-Request-ID, which also appears in LOG entries for that call.
API-F09MustPaginate list endpoints.Lists return a page of results and a cursor or offset for the next page; proposed default page size 50.
API-F10ShouldSupport idempotency keys on create calls from integrations.Repeating a POST with the same key returns the original result instead of a duplicate.
API-F11MustIntroduce breaking changes only under a new version path.A removed or renamed field ships under /api/v2; /api/v1 keeps working until retired with notice.
API-F12ShouldRestrict cross-origin access to known NUMIC front ends.Requests from other origins are rejected by CORS policy.

Non-functional requirements

IDPriorityRequirementAcceptance criterion
API-N01ShouldScore quickly.Proposed: stateless scoring under 300 ms at p95; store-and-score under 500 ms at p95.
API-N02MustNever write request bodies containing patient data to application logs.A log-scrubbing test confirms no MRN, name or date of birth appears in logs.
API-N03MustKeep the API layer thin.Route handlers contain no threshold logic; tests show scoring results come only from SCR.
API-N04ShouldBe covered by contract tests generated from the OpenAPI schema.CI fails if a response does not match its declared schema.
