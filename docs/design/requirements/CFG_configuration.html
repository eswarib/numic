NUMIC requirements / Cross-cutting

Configuration

Hold every setting that changes how a deployment runs but never changes a score. Deployment settings come from environment variables and are checked when the app starts. Unit settings, such as band wording and scan intervals, are stored in the database and edited by admins. Clinical scoring parameters are deliberately not here: they live only in versioned rule-set revisions managed by the rule engine.

Scope

In scope

  • Tier 2 deployment settings with the NUMIC_ prefix
  • Startup validation of settings
  • Unit-level settings stored in the database
  • Frontend settings for the demo (config.js)
  • Handling of secrets

Out of scope

  • Tier 1 clinical parameters: thresholds, points, band cut-offs, minimum-band rules (owned by RUL)
  • Identity-provider configuration on the trust side (owned by IAM and trust IT)

Users, data and interfaces

Users and callers

  • Trust IT and the NUMIC operations team (deployment settings)
  • Admins (unit settings)
  • Engineers (demo and frontend settings)

Data it owns

  • Deployment settings (environment)
  • Unit settings: band labels, suggested-action text, surveillance intervals per band, unit time zone
  • Demo settings in config.js

Interfaces

  • Settings class in core/config.py (extended)
  • GET /api/v1/config/public: non-secret settings the frontend needs
  • GET/PUT /api/v1/units/{id}/settings (admin)
  • config.js for the static demo

IDPriorityRequirementAcceptance criterion
CFG-F01MustDeployment settings are read from environment variables with the NUMIC_ prefix, keeping the existing NUMIC_DATABASE_URL and NUMIC_DATABASE_ECHO.Starting the app with these variables set changes the database it connects to; no code change needed.
CFG-F02MustAdd NUMIC_DEFAULT_SCORE_VERSION (default numic_flow_levene) and NUMIC_ENABLED_SCORE_VERSIONS (default both rule sets).A request with no rule set uses the configured default; a disabled rule set is missing from /score/versions.
CFG-F03MustAdd NUMIC_SCAN_DAY_TIMEZONE (default Europe/London) to define the calendar day used for day of life.A scan at 00:30 BST is counted on the local date, not the previous UTC date.
CFG-F04MustAdd NUMIC_CAPTURE_DECISIONS (on/off) and NUMIC_MIN_CASES_FOR_SUGGESTION.With capture off, the decision panel is hidden and the decision endpoint returns 404.
CFG-F05MustAdd identity-provider settings (issuer URL, client ID, allowed audiences) and NUMIC_LOG_LEVEL.Changing the log level to DEBUG in staging increases log detail without a rebuild.
CFG-F06MustAll settings are checked when the app starts, and the app refuses to start with a missing or invalid value.An unknown default rule set or an invalid time-zone name stops startup with a message naming the variable.
CFG-F07MustClinical scoring parameters are never read from environment variables or unit settings. They come only from published rule-set revisions.A code search finds no threshold, points or cut-off values in core/config.py; changing an env variable cannot change a score.
CFG-F08MustUnit settings are stored in the database and edited by admins: band labels, suggested-action text, surveillance interval per band, and unit time zone.An admin changes the moderate-band label; the clinician app shows the new label without a restart; the change is audited.
CFG-F09MustUnit settings start from sensible defaults when a unit is created.A new unit shows default band labels and intervals before an admin edits them.
CFG-F10MustSecrets (database password, client secrets, signing keys) are supplied from the hosting secret store, never committed to the repository.A repository secret scan in CI finds no secrets; the app reads them from the environment at startup.
CFG-F11MustThe static demo reads its settings from config.js: API base path, feature flags, band wording, disclaimer text and default date of birth.Changing the disclaimer text in config.js changes the demo banner with no other edits.
CFG-F12ShouldNon-secret settings the frontend needs are served from one endpoint so the apps do not hard-code them.GET /api/v1/config/public returns enabled rule sets, capture flag and unit labels, and no secrets.
