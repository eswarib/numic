NUMIC requirements / Front end

Admin console

The admin console is where the clinical rule configuration is managed without code changes. An admin opens a published rule set, edits a pre-filled draft, checks it and previews its impact; a different person with the approver role publishes it as a new revision. The console also manages user roles and unit scoping, unit settings, the audit trail viewer, and the learning-loop dashboards.

Scope

In scope

  • Login
  • Rule-set list and revision history
  • Rule editor, diff and impact preview
  • Approval and rollback
  • Users, roles and unit scoping
  • Unit settings
  • Audit viewer
  • Agreement dashboard and suggestion review

Out of scope

  • Scoring logic itself (SCR)
  • Identity provider administration (IAM, hospital IdP)
  • Running the regression job (LRN)

Users, data and interfaces

Users and callers

  • Admin (clinical informatics or the NUMIC lead at a site)
  • Approver (unit clinical lead)
  • Clinical safety officer reviewing changes

Data it owns

  • None directly. All changes go through API to RUL, PAT, IAM and CFG.

Interfaces

  • /api/v1/admin/rule-sets (list, draft, edit, validate, preview, submit, approve, reject, rollback, retire)
  • /api/v1/admin/users and role assignments
  • /api/v1/units/{id}/settings
  • /api/v1/audit
  • /api/v1/analytics/agreement and /api/v1/analytics/suggestions

IDPriorityRequirementAcceptance criterion
ADM-F01MustRequire login through IAM and show only the functions the user's role allows.A clinician-role user cannot open the rule editor; the menu item is hidden and the API returns 403.
ADM-F02MustList rule-set families with their revisions, status (draft, published, retired), active flag, author, approver and dates.numic_flow_levene shows revision 1 as published and active after first deployment.
ADM-F03MustCreate a draft from a published revision with every Tier 1 parameter pre-filled, grouped by layer: age and reference tables, static thresholds per metric, progression, clinical points, layer weights, band cut-offs, minimum-band rules and first-scan policy.Opening Edit on revision 1 shows today's values (e.g. AHW 6 / 10 mm, TOD 25 / 30 mm, band cut-offs 3 / 7).
ADM-F04MustValidate a draft as values change and before submission, showing each problem next to the field.Setting moderate cut-off below low cut-off shows an error and blocks submission.
ADM-F05MustShow the differences between a draft and the revision it came from.A changed TOD threshold appears as 30 mm to 28 mm in the diff.
ADM-F06MustPreview the impact of a draft by re-scoring recent stored assessments and listing the cases whose band would change.Proposed default: last 500 assessments; the preview shows counts per band change and lets the user open each case.
ADM-F07MustSubmit a draft for approval with a reason, and let an approver approve or reject it with a reason.The author of a draft cannot approve it; approval publishes it as the next revision, e.g. numic_flow_levene@2.
ADM-F08MustRoll back by making an earlier published revision active again.After rollback, new scores use the earlier revision and stored results keep their original revision.
ADM-F09MustManage user roles (viewer, clinician, admin, approver) and the units each user can access.Removing a user's access to a unit takes effect on their next request.
ADM-F10MustManage unit settings: time zone for the scan day, surveillance intervals per band, band labels and suggested-action wording.Changing the low-band interval changes DSH overdue flags for that unit only.
ADM-F11MustSearch, filter and export the audit trail.Filtering by rule-set revision shows its draft, edits, approval and publication events with actors and times.
ADM-F12ShouldShow the agreement dashboard from LRN.Shows the predicted versus clinician band table for a chosen unit, revision and date range.
ADM-F13ShouldReview threshold suggestions from LRN and turn a suggestion into a draft.A suggestion opens as a draft with its evidence attached and follows the normal approval path.
ADM-F14CouldRetire a rule-set family or revision.Requests naming a retired revision return 422 listing valid IDs.
