NUMIC requirements / Core logic

Measurement capture & integration

Measurement capture brings ultrasound measurements into NUMIC from manual entry, spreadsheets, overlay or PACS feeds and, later, image analysis. It validates values, records where each value came from and who measured it, and links each measurement to a patient and scan time. Corrections never overwrite the original value.

Code MEALayer Core logic Partly exists Manual entry, spreadsheet import (CSV/XLSX), overlay/PACS numeric feed, coronal landmark calipers and DICOM loading exist in src/numic/measurement/. Scope

In scope

  • Manual entry of VI left and right, AHW, TOD and scan date/time
  • CSV/XLSX import with per-row errors
  • Overlay/PACS numeric feeds
  • Landmark calipers to mm
  • Provenance and corrections

Out of scope

  • Scoring (SCR)
  • Patient demographics (PAT)
  • Automatic image measurement before clinical validation (EXT)

Users, data and interfaces

Users and callers

  • Clinicians and sonographers (manual entry)
  • Data managers (spreadsheet import)
  • Integrations (overlay/PACS feeds)

Data it owns

  • Imaging studies (scan date/time, source)
  • Measurements: VI left/right, AHW, TOD in mm, measured_by, entry_source, version

Interfaces

  • /api/v1/measurement/* endpoints via API
  • Spreadsheet import endpoint
  • CLI numic-manual-measure

Functional requirements

Must needed for a first clinical pilot Should expected soon after Could useful if time allows Later future phase
IDPriorityRequirementAcceptance criterion
MEA-F01MustAccept VI (left and right), AHW and TOD in mm with scan date/time and who measured them.A manual entry with these fields is stored and returned with an ID.
MEA-F02MustStop accepting VI percentile and VI reference values as inputs.Requests containing vi_percentile or vi_p97_reference_mm are rejected with 422 naming the field.
MEA-F03MustValidate values: positive numbers within configurable plausible ranges.A negative TOD or a VI above the configured maximum is rejected with the field and allowed range.
MEA-F04MustImport CSV and XLSX files with column aliases and report errors per row without rejecting the whole file.A file with 10 rows, 2 invalid, imports 8 rows and lists the 2 row numbers with reasons.
MEA-F05MustAccept numeric feeds from overlay or PACS systems.An overlay payload with patient reference and scan time creates a measurement with entry_source overlay.
MEA-F06ShouldConvert coronal landmark calipers to mm using pixel spacing.Existing landmark tests still pass after the percentile fields are removed.
MEA-F07MustRecord entry source and provenance for every measurement.Each measurement shows entry_source (gui, cli, tabular, overlay, landmarks, image) and measured_by.
MEA-F08MustLink every measurement to a patient and a scan date/time.A measurement for an unknown patient reference is rejected or queued, never stored unlinked.
MEA-F09ShouldWarn about likely duplicates for the same patient and scan time.A second entry within the same minute for the same patient shows a duplicate warning.
MEA-F10MustKeep corrections as new versions linked to the original.Correcting AHW from 6.0 to 6.4 keeps both values, and results show which version they used.
MEA-F11LaterExtract measurements automatically from images only after clinical validation, flagged as automatic.Image-derived values are marked entry_source image and require confirmation before scoring.
