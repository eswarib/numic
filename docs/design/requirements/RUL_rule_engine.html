NUMIC requirements / Core logic

Rule engine

The rule engine owns the clinical configuration that the scoring engine applies. It stores rule sets as families with immutable published revisions, supports editing through drafts with validation, impact preview and approval, and holds the Levene and Brouwer reference tables. Every score can be traced to the exact revision that produced it.

Scope

In scope

  • Rule-set families and revisions (family@n)
  • Draft, validate, impact preview, approve, publish, rollback, retire
  • Factory seed files for numic_flow_levene and numic_flow_brouwer
  • Reference tables with source citations
  • Validated parameter ranges

Out of scope

  • Applying rules to a case (SCR)
  • Login and role checks (IAM)
  • Admin screens (ADM)
  • Deployment settings (CFG)

Users, data and interfaces

Users and callers

  • Admin console (drafting, approval, rollback)
  • Scoring engine (reads revisions)
  • API layer (resolves the requested or default rule set)
  • Learning loop (saves threshold suggestions as drafts)

Data it owns

  • Rule-set families and revisions (config, status, author, approver, timestamps, reason)
  • Reference tables (Levene VI 97th; Brouwer VI, AHW, TOD 97.5th) with source and checksum

Interfaces

  • get_active(family) → Revision, get(family@n)
  • Admin endpoint group /api/v1/admin/rule-sets via API
  • JSON export of a revision for the browser demo

Functional requirements

IDPriorityRequirementAcceptance criterion
RUL-F01MustStore rule sets as families with numbered revisions identified as family@n, each with status draft, published or retired.numic_flow_levene@1 and numic_flow_brouwer@1 exist after first start; IDs are 32 characters or fewer.
RUL-F02MustSeed revision 1 of numic_flow_levene and numic_flow_brouwer from factory JSON files on first start.An empty database starts with both families published at @1 and values equal to the seed files.
RUL-F03MustMake published revisions immutable.Any attempt to change a published revision returns 409 and nothing changes.
RUL-F04MustCreate a draft from any published revision with every value pre-filled.A new draft of numic_flow_levene@1 has identical values and status draft.
RUL-F05MustValidate a draft before it can be submitted: thresholds increase, points are within allowed ranges, band cut-offs fit the maximum score, named reference tables exist, offsets are not negative.A draft with moderate cut-off below the low cut-off is rejected with a message naming both fields.
RUL-F06ShouldPreview the impact of a draft by re-scoring recently stored assessments and listing band changes.Preview over the last 500 assessments (proposed default) shows counts per band change and the affected cases.
RUL-F07MustPublish a draft only when a user with the approver role, who is not the draft's author, approves it with a reason.The author's own approval is refused with 403; an approver's approval creates family@n+1 as active.
RUL-F08MustAllow rollback by making an earlier published revision active again.After rollback new scores use the earlier revision; past results keep their original revision ID.
RUL-F09MustReject requests that name a retired or unknown rule set with 422 listing the valid IDs.A request for numic_flow_v1 returns 422 listing numic_flow_levene and numic_flow_brouwer.
RUL-F10MustHold the Levene and Brouwer reference tables as versioned reference data with source citation and checksum.Each table records its source paper and checksum; a changed table requires a new revision.
RUL-F11MustShow the differences between any two revisions.A diff of @1 and @2 lists every changed parameter with old and new values.
RUL-F12ShouldEnforce configurable validated ranges per parameter to limit what sites may change.An edit outside the validated range for AHW cut-offs is refused with the allowed range.
RUL-F13MustRecord every draft, edit, approval, publish, rollback and retire in the audit trail.Each action produces an audit entry with actor, time, before and after values and reason.
RUL-F14ShouldExport a published revision as JSON in the shared format used by the browser demo.The exported file loads in the demo and reproduces the server's scores on the shared test corpus.
