NUMIC requirements / Core logic

Patient & unit management

This component holds the NICU units and the babies in them. Each baby has a hospital reference, date of birth and gestational age at birth, which the scoring engine needs to work out age at scan. It records admission, transfer and discharge so dashboards show only babies currently on the unit.

Code PATLayer Core logic Not built PatientInfo schema has optional date_of_birth and a gestational_age_weeks documented as GA at scan. The database Patient table holds only external_ref and metadata. No NICU unit model. 10 functional · 3 non-functional · 11 must
Version 15 Oct 2026Change history

Scope

In scope

  • NICU units with site and time zone
  • Patients: MRN, date of birth, gestational age at birth (weeks + days), optional names
  • Admission, transfer, discharge
  • Active patient lists and search

Out of scope

  • Measurements (MEA)
  • Scoring (SCR)
  • Hospital ADT integration (EXT)

Users, data and interfaces

Users and callers

  • Clinicians (register and find babies)
  • Unit dashboard (active babies)
  • Admins (units, merges)

Data it owns

  • Units (name, site, time zone, settings)
  • Patients (external reference, date of birth, gestational age at birth, optional names)
  • Unit stays (admitted, transferred, discharged timestamps)

Interfaces

  • /api/v1/units, /api/v1/patients via API

Functional requirements

Must needed for a first clinical pilot Should expected soon after Could useful if time allows Later future phase
IDPriorityRequirementAcceptance criterion
PAT-F01MustStore NICU units with name, site and time zone.A unit created with Europe/London is used as the scan-day time zone for its patients.
PAT-F02MustStore each baby's hospital reference, date of birth and gestational age at birth as weeks and days.Patient with GA 27+3 is stored as weeks 27, days 3 and shown as 27+3.
PAT-F03MustReplace the existing gestational_age_weeks field, documented as GA at scan, with gestational age at birth.No API schema or table field named gestational_age_weeks remains.
PAT-F04MustValidate gestational age at birth against a configurable plausible range (proposed 22+0 to 42+6).GA 45+0 is rejected with the allowed range.
PAT-F05MustRecord admission, transfer between units and discharge with timestamps.A transferred baby appears on the new unit's list and not the old one.
PAT-F06MustList active babies per unit.The list shows only babies admitted and not discharged from that unit.
PAT-F07MustFind a baby by hospital reference.Searching an MRN returns that baby if the user can access their unit.
PAT-F08MustFlag stored results for re-scoring when date of birth or gestational age changes.After correcting the date of birth, affected results show "inputs changed, re-score needed".
PAT-F09ShouldLet an admin merge duplicate patient records, keeping history.Merging two records keeps all scans and results under one patient and audits the merge.
PAT-F10CouldMake names optional so units can work with hospital reference only.A patient without names can be created and used everywhere.

Non-functional requirements

IDPriorityRequirementAcceptance criterion
PAT-N01MustEnforce unit-scoped access through IAM.A clinician from unit A gets 403 for a patient on unit B.
PAT-N02MustAudit every create, update, transfer, discharge and merge.Each action produces an audit entry.
PAT-N03MustTreat date of birth and names as identifiable data under SEC rules.These fields never appear in application logs or analytics extracts.
