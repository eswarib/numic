NUMIC requirements

Requirements for each component of NUMIC, the neonatal PHVD decision-support system. Each component has its own page with scope, functional and non-functional requirements, acceptance criteria, dependencies and open questions. Component boundaries and flows are described in NUMIC system architecture.

How to read these documents

  • IDs are CODE-F01 for functional and CODE-N01 for non-functional requirements. They stay stable so tests, tickets and the clinical safety hazard log can refer to them.
  • Priorities: Must needed for a first clinical pilot, Should expected soon after, Could useful if time allows, Later future phase.
  • Proposed numbers (timeouts, latency targets, retention periods) are starting points to confirm with clinical, quality and IT leads.
  • Clinical values such as thresholds are not fixed here. They live in rule-set revisions managed by the rule engine (RUL) and approved through the admin console (ADM).
