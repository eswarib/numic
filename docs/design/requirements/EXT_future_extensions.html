NUMIC requirements / Extensions

Future extensions

Collect the features planned after the core product, so their constraints are clear early. These connect NUMIC to hospital systems (imaging, records, admissions), automate measurement from images, and alert staff. Each one is switched off by default, uses the same public API as the rest of NUMIC, and never bypasses human review.

Scope

In scope

  • PACS / DICOM SR measurement import
  • Export of results to the electronic health record (FHIR)
  • ADT feed for patient admission, transfer and discharge
  • Image-based automatic measurement
  • Notifications for rising band or overdue scan
  • Benchmarking across units

Out of scope

  • Core scoring and rules (SCR, RUL)
  • Manual and spreadsheet entry (MEA)
  • Learning loop (LRN)

Users, data and interfaces

Users and callers

  • Clinicians and sonographers
  • Trust integration and imaging teams
  • Unit leads (benchmarking)
  • Engineers

Data it owns

  • Integration settings per trust
  • Inbound message log (no identifiers in app logs)
  • Notification rules and delivery records

Interfaces

  • DICOM SR or PACS overlay feed into the measurement API
  • FHIR resources (e.g. Observation, DiagnosticReport) sent to the trust's records system
  • HL7 v2 or FHIR ADT feed into patient management
  • Notification channels (in-app first, others later)

IDPriorityRequirementAcceptance criterion
EXT-F01MustEvery extension is behind its own feature flag and is off by default.With flags off, no integration endpoints are reachable and no background jobs run.
EXT-F02MustExtensions use the same public API and permission checks as the apps, through service accounts with scoped tokens.An integration token without measurements:write cannot create measurements.
EXT-F03MustNo extension changes a band, publishes a rule revision or records a decision without a person confirming it.Imported measurements appear as 'awaiting review' until a clinician accepts them.
EXT-F04ShouldImport VI, AHW and TOD from PACS measurements or DICOM structured reports, matched to the right patient and scan.A test DICOM SR with known values creates a measurement linked to the matching patient and scan time.
EXT-F05ShouldSend each finalised result to the trust's electronic health record as FHIR resources.A result accepted by the clinician appears in a FHIR test server with the band, layer scores and rule revision.
EXT-F06ShouldReceive admissions, transfers and discharges from the trust's ADT feed so the unit list stays current.An ADT discharge message moves the baby off the unit dashboard's active list.
EXT-F07LaterMeasure VI, AHW and TOD automatically from ultrasound images with a validated model, shown to the clinician for confirmation.Automatic values are labelled as model-derived, need clinician acceptance, and the feature stays off until a clinical validation study is complete.
EXT-F08ShouldNotify the care team when a baby's band rises to high, or a scan is overdue for the unit's surveillance interval.Raising a seeded case to high creates an in-app notification for clinicians in that unit.
EXT-F09CouldLet units compare anonymised band distributions and agreement rates with other units.The benchmark view shows only aggregated counts, never patient-level data from another unit.
EXT-F10MustEvery inbound and outbound message is audited, and failures are retried and reported.A failed FHIR send is retried and, after the retry limit, appears as an alert.
