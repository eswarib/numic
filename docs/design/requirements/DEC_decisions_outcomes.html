NUMIC requirements / Core logic

Decisions & outcomes

When enabled for a deployment, clinicians can record the band they actually decided after seeing NUMIC's result, with when and why. Outcome events such as lumbar puncture, reservoir or shunt are recorded separately. Together these provide the predicted band, actual band and outcomes that the learning loop needs.

Scope

In scope

  • Clinician decision per result
  • Reason codes and action taken
  • Outcome events with dates
  • Corrections by superseding records

Out of scope

  • Scoring (SCR)
  • Analysis and threshold suggestions (LRN)

Users, data and interfaces

Users and callers

  • Clinicians (record decisions and outcomes)
  • Learning loop (analysis)
  • Unit dashboard (pending decision flag)

Data it owns

  • Clinical decisions (risk_report_id, decided_band, agrees_with_predicted, decided_at, recorded_at, decided_by, reason codes, notes, action taken, supersedes_id)
  • Outcome events (patient, type, occurred_at, recorded_by, notes)

Interfaces

  • /api/v1/assessments/{id}/decision, /api/v1/patients/{id}/outcomes via API

Functional requirements

Must needed for a first clinical pilot Should expected soon after Could useful if time allows Later future phase
IDPriorityRequirementAcceptance criterion
DEC-F01MustLet a deployment switch decision capture on or off.With NUMIC_CAPTURE_DECISIONS=false the decision endpoints return 404 and the UI hides the panel.
DEC-F02MustRecord the clinician's band (low, moderate, high) against a stored result.A decision links to exactly one RiskReport and stores the band.
DEC-F03MustWork out agreement with NUMIC's band automatically.NUMIC moderate and clinician low stores agrees_with_predicted false.
DEC-F04MustStore when the decision was made, defaulting to now and editable, and when and by whom it was recorded.decided_at can be set to an earlier time; recorded_at and decided_by are set by the system and cannot be edited.
DEC-F05MustRecord reason codes from a configurable list plus optional notes.Default codes include clinical picture, doubt about the measurement, local protocol, other.
DEC-F06ShouldRecord the action taken.Options include routine scans, increased surveillance, lumbar puncture, neurosurgical referral, reservoir.
DEC-F07MustMake decisions append-only; a correction is a new record that supersedes the previous one.Delete is not available; a correction shows both records with the supersedes link.
DEC-F08MustRecord outcome events with type and date.Types include lumbar puncture, reservoir, ventricular subgaleal shunt, VP shunt, ETV, death, discharge.
DEC-F09MustList decisions and outcomes per patient and per unit.A patient view lists decisions with their results; a unit list can be filtered by date.
DEC-F10CouldSupport a blinded mode where the clinician records their band before seeing NUMIC's.In blinded mode the result is hidden until a band is recorded.
DEC-F11LaterRecord neurodevelopmental follow-up outcomes.A follow-up outcome type exists with assessment date and summary score.

Non-functional requirements

IDPriorityRequirementAcceptance criterion
DEC-N01MustNever hard-delete decisions or outcomes.No delete endpoint exists; database permissions prevent deletes for the app user.
DEC-N02MustAudit every decision, correction and outcome.Each produces an audit entry.
DEC-N03MustKeep this data out of the public demo.The demo has no decision or outcome features and sends no data to a server.
